### #1 · 网络模块架构搭建

**时间**：2026-04-25

**背景**：团队开始 Phase 3 PVP 开发，需要确定网络层架构

**做了什么**：
- 设计三层架构：
  - `protocol/` — 消息定义（Packet / Serializer / Deserializer / ProtocolDef）
  - `session/` — 连接管理（GameServer / GameClient / LobbyManager / RoundManager）
  - `sync/` — 业务同步（RandomSynchronizer / DeploymentSync / ClashSync / StateValidator）
- 引入 Qt 信号槽机制实现解耦（网络层不碰 UI）
- 固定包头设计：`msgType[1] + bodyLen[2] + body[]`

**结论**：架构稳定，后续改动均在协议内容层，不改变整体分层

### #3 · 怪物波次同步方案确定

**时间**：2026-04-28

**背景**：最初设计的 `WaveData` 包含 `quint8 monsters[8]` 怪物数组，经讨论发现这是错误设计

**问题**：
```
错误设计（已废弃）：
struct WaveData {
    quint8 waveId;
    quint8 monsterCount;
    quint8 monsters[8]; // 直接传怪物类型列表
};
问题：①浪费带宽 ②破坏 RNG 一致性（双方计算可能不一致）
```

**讨论结论**：
- 改用**种子同步**方案
- Host 在 GAME_START 时生成随机种子，广播给 Client
- 双方用同一个 `std::mt19937(seed)` 初始化本地 RNG
- 每波 Host 只广播 `waveId`（波次编号）
- 双方各自调用 `rng().randomInt()` 生成完全一致的怪物序列

**正确设计（现行）**：
```cpp
struct WaveStartPayload {
    quint8  waveId;       // 波次编号（从 1 开始）
    quint8  reserved[3];  // 保留，填 0
};
```

**废弃结构**：`WaveData.monsters[8]` 已从 ProtocolDef.h 中删除
