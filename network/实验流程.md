### #3 · 怪物波次同步方案确定

**时间**：2026-04-28

**背景**：最初设计的 `WaveData` 包含 `quint8 monsters[8]` 怪物数组，经讨论发现这是错误设计

**问题**：
```
错误设计（已废弃）：
struct WaveData {
    quint8 waveId;
    quint8 monsterCount;
    quint8 monsters[8]; // 直接传怪物类型列表
};
问题：①浪费带宽 ②破坏 RNG 一致性（双方计算可能不一致）
```

**讨论结论**：
- 改用**种子同步**方案
- Host 在 GAME_START 时生成随机种子，广播给 Client
- 双方用同一个 `std::mt19937(seed)` 初始化本地 RNG
- 每波 Host 只广播 `waveId`（波次编号）
- 双方各自调用 `rng().randomInt()` 生成完全一致的怪物序列

**正确设计（现行）**：
```cpp
struct WaveStartPayload {
    quint8  waveId;       // 波次编号（从 1 开始）
    quint8  reserved[3];  // 保留，填 0
};
```

**废弃结构**：`WaveData.monsters[8]` 已从 ProtocolDef.h 中删除

### #5 · Serializer/Deserializer 完整实现 + PING/PONG 修复 + NetworkTest v2

**时间**：2026-04-28

**背景**：`Serializer.h` 和 `Deserializer.h` 只有头文件声明，没有具体实现；PING/PONG 心跳逻辑存在 bug；NetworkTest v1 用字符串模拟 ROUND_VALUE。

**做了什么**：

1. **Serializer/Deserializer 实现**
   - 补充了所有 Payload 结构体的 `serialize()` 和 `decode()` 方法
   - 添加了大厅消息辅助函数：`buildJoinRoom` / `buildJoinAck` / `buildGameStart` / `buildSyncSeed` 及对应 decode
   - WAVE_START 正式使用 `WaveStartPayload`（4 字节二进制）

2. **PING/PONG 心跳修复**
   - 旧逻辑：收到 PING 未正确回 PONG，收到 PONG 未重置计时器
   - 新逻辑：Server 每 2s 发 PING → Client 回 PONG → 收到 PONG 重置计时器；反之 Client 发 PING → Server 回 PONG
   - 超时判定断线

3. **新增 Reconnecting 状态**
   - `NetworkState.h` 添加 `Reconnecting` 枚举值
   - `NetworkManager.h/cpp` 添加 `reconnect()` 方法，Client 断线后自动尝试恢复

4. **编译修复**
   - `Serializer.h:80` 用 `d.push_back(3, '\0')`，`QByteArray::push_back` 不支持双参数
   - 修复为 `d.append(3, '\0')`

5. **NetworkTest v2**
   - `net_test/main.cpp` 升级为 v2：ROUND_VALUE → WaveStartPayload
   - 完整演示 `Serializer::serialize(WaveStartPayload)` 和 `Deserializer::decode(WaveStartPayload)`
   - PING/PONG 心跳日志

**产物**：6 个头文件修改（Serializer.h / Deserializer.h / ProtocolDef.h / NetworkState.h / NetworkManager.h / NetworkClient.h），1 个测试程序升级

**结论**：
- Serializer/Deserializer ✅ 完成，可供 PVP 组调用
- PING/PONG ✅ 完成，断线检测可用
- `Reconnecting` 状态 ✅ 完成，断线重连机制就绪

### #6 · 确定性问题：减少同步消息，靠模拟一致性保证

**时间**：2026-04-28

**背景**：README 中有一系列"谁来发 CORE_HP_SYNC / RESOURCE_SYNC / UNIT_DESTROYED / GAME_OVER"的问题，归根结底是在问"战斗过程中的结果要不要网络同步"。

**讨论结论**：
- ✅ 基地血量变化、怪物死亡、胜负判定——**不需要网络同步**
- 原因：双方持有相同 RNG 种子 + 相同部署输入 → 模拟结果天然一致
- 只需要同步"头尾"：开局部署 + 每波 waveId，中间过程靠确定性模拟

**PVP 组只需要同步**：
1. 部署结果（DEPLOYMENT_END 后 Host 广播）
2. 波次编号（WAVE_START）
3. 玩家主动操作（升级 UPGRADE_UNIT / 撤回 RECALL_UNIT）

**结论**：
- 删除 README 中"谁来发 CORE_HP_SYNC"等问题列表（这些不需要同步）
- 网络层只需要提供部署同步 + 波次触发 + 玩家操作转发
- 战斗模拟的中间结果（伤害/死亡/血量变化）不需要任何网络消息
